The loop

One question can need several tools before there is an answer. The loop keeps going until the model stops asking.

1
Send the whole message list, with every tool schema attached.
2
The reply comes back as a list of blocks, not one string. Usually a text block saying what it is doing, then one tool_use block per tool it wants.
3
Append that entire content list to history, tool_use blocks included. Drop them and the next call breaks.
4
Run every requested tool. Send one tool_result back per request, with tool_use_id matched to the block that asked. A tool that throws returns a result with is_error, never an exception.
5
Repeat while stop_reason == "tool_use". Anything else means the answer is ready.

Three rules that keep it honest

Every id gets an answer. The model can ask for several tools in one message. Each tool_use needs its own tool_result with the id matched, even when the results come back in a different order.
Errors travel as results. A failed tool returns is_error: true with a message written for the model to read, so it can correct itself and try again. An exception would end the turn instead.
The caveat rides with the data. The disclaimer is inside every tool result, not only in the system prompt, so it reaches the answer even after a long chain of calls.

Decision support. Conditions are reported against the operator's own thresholds. This is not a statement that a departure is safe. The operator on the water owns the go or no-go call. Tide is not included.
